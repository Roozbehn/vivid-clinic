# Vivid Clinic (`vivid.clinic`)

Framework-free static site (HTML + one CSS file + vanilla JS) generated by Node
scripts, plus one Cloudflare Pages Function for the booking API. Zero runtime npm
dependencies. Node `>=18`. See `README-reviews.md`, `README-booking.md`,
`I18N-SPEC.md`, and `package.json` scripts for full details.

## Cursor Cloud specific instructions

The update script runs `npm install` on startup. Because `package.json` declares no
dependencies, this installs nothing — no other dependency setup is required (Node,
Python 3, and `npx` are already present).

### Building and running (services)

`dist/` is **git-ignored and not committed** — you must build it before serving or
running the booking API, and rebuild after editing anything under `src/`,
`functions/`, `scripts/`, or `src/data/`.

- Build first: `npm run build` (writes `dist/`). Standard scripts live in `package.json`.
- Static preview: `npm run serve` → http://localhost:8787 (uses `python3 -m http.server`).
  This serves `dist/` only; the `/api/booking` endpoint does NOT exist here.
- Full app incl. booking API: `npx wrangler pages dev dist --port 8788` → serves
  `dist/` + `functions/` so `POST /api/booking` works. On first run `wrangler` is
  downloaded via `npx` (can take ~30–60s); it is not a committed dependency.

### Testing / linting

- No linter or formatter is configured.
- Booking backend tests: `npm run test:booking`.
- Review dataset validation: `npm run validate`.
- Extra checks are run directly (not in `package.json`): `node scripts/verify-i18n.mjs`,
  `node scripts/test-review-url.mjs`, `node scripts/check-phase0-css.mjs`,
  `node scripts/check-phase0-images.mjs`.
- Known pre-existing failure: `verify-i18n.mjs` reports 2 `7-en-diff` failures because
  the `baseline/` snapshot it diffs against is absent from the repo (it points at a path
  from the original author's machine). The other 1072 i18n assertions pass. This is
  unrelated to environment setup.

### Booking API caveats (for end-to-end testing)

- The API has anti-spam checks: a filled `meta.honeypot` is rejected, and a submission
  where `meta.submittedAt - meta.formStartedAt < 3000ms` is rejected as `too_fast`. When
  POSTing directly (curl), set `meta.formStartedAt` well in the past so the elapsed time
  exceeds 3s.
- CORS allow-list includes `http://localhost:8787/8788` and `127.0.0.1` variants; send a
  matching `Origin` header when testing cross-origin.
- With no `RESEND_API_KEY`/`CLINIC_NOTIFY_EMAIL` set, a valid submission returns
  `{ ok: true, notified: false }` — this is expected (WhatsApp fallback is the delivery
  channel). All external services (Google Business Profile import, Resend email) are
  optional and configured via `.env` / Cloudflare env vars; nothing runs locally.
